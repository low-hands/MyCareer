# 第 2 步：每个动作工具自己的动作词

在 `CapabilityDescriptor` 增加 `action_terms_zh`，按工具职责逐项声明和审核，共覆盖 36 个模型可调用 WRITE 和 5 个 READ proposal。普通读工具与运行时专用工具不声明该字段。目录构建时拒绝漏填、空白或重复动作词，契约测试覆盖全部模型可调用写工具及 proposal。

query 搜索动作工具时，必须命中该工具自己的动作词，或完全等于它的名称/完整别名。这替代动作工具原来的“两词重叠”证据门槛；BM25 和原有例句得分仍决定排序。普通 READ 保留第 1 步的动态门槛。词法、语义候选都调用共用动作分类与证据函数。

精确 `names` 加载保持原样，包括按 namespace 加载其所有工具。只有 query 的精确工具名或完整别名豁免动作词；query 仅等于 namespace 不再豁免动作工具。例如 `query="resume.match"` 可召回该 namespace 的读工具，写工具 `match_resume_to_job` 则须用名称、别名或动作描述检索；`names=["resume.match"]` 仍加载二者。

`needs_action_evidence` 的唯一实现移到 catalogue，供目录验证和 search 共用；search 保留导入路径兼容。动作词不加入 BM25 或 embedding 文本，不改 provider schema，因此录制语义分数继续有效，无需重录或评分 holdout。

## 元数据审核要点

- 起草工具包括起草、定制、生成和改写简历的明确表达；导出工具仅含导出、下载。
- 创建投递包括创建、登记、加入、建立等；这些词不会自动成为其他工具的动作词。
- `记录` 也可能是“投递记录”中的名词，创建面试、复盘、事实提案及便笺改用“记录面试”“记录复盘”“记录经历”“记录笔记”等明确短语，避免仅靠该名词放行。
- 开发集检查补全了各工具职责内的常见动作表达，例如分析的“拆一下”、调研的“查查”、模拟面试启动的“来一场”。未修改目录别名、摘要、例句或固定评估用例。
- 动作词匹配仍是子串匹配，不解析否定、时态或一词多义。比如“生成”可同时放行不同生成工具；这一步不能保证完全没有非目标动作暴露。

## 门槛效果与名次效果的区别

- 模型风格基线的 8 次禁止动作暴露全部被新门槛拒绝，未归因为读工具挤占名次。
- 基线的 7 次非目标 WRITE 全部被新门槛拒绝；另有 2 次新的非目标 WRITE 进入前五，均来自“帮我生成一份定制简历”：`prepare_interview`、`prepare_interview_calendar_sync` 也含“生成”。因此净计数为 7→2，不能声称这类误带已消除。

runtime 计数还受已加载工具、状态门槛、主动读回和可达性约束影响，24→7 是端到端观测，不把它简单等同于 17 次 query 门槛拒绝。上述逐条归因仅针对直接 search_catalog 的两组开发集。
