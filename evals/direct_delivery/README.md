# 工具回执交付

## 当前行为

- **终点工具**：只有 `export_resume_artifact` 默认直接交付。成功导出且有 artifact ID、本轮没有其他业务结果、失败或待续交互时，运行时直接结束本轮，不再调用模型（见 `agent/presentation/receipt_completion.py`）。
- 简报、空列表、面试回执等其他结果都继续由模型回复。
- **资源卡片提前推送**：报告、岗位等已持久化的资源，在工具返回后立即推送卡片，模型回复继续生成；资源 ID 在本轮内去重，最终不重复发卡。失败、未提交的写入和合成拒绝不提前发卡。

## 结论

曾尝试过两种更激进的方案，都已撤回：

1. **按用户措辞的正则**判断是否直接交付——规则脆弱，已弃用；
2. **模型声明 `deliver_direct`**（模型在工具调用里声明"这一步就是终点"）——在 Qwen 上不可靠，判断错误时会提前结束本轮、漏掉后续步骤。

因此只保留由代码判定、出错代价低的终点工具。延迟改从资源卡片提前推送、后台摘要等方向入手，见 [延迟基线](../latency/README.md)。
